先說：什麼是 dotfile / Linux ricing

  • dotfile ＝ home 底下、檔名以 . 開頭的設定檔（.config/、.bashrc、hyprland.conf...）
  • Linux 把桌面、視窗、面板、字型、鍵盤幾乎全部都用純文字檔描述
  • ricing ＝ 把這些檔案改成自己想要的樣子，從外觀到工作流程通通客製
  • 同一台機器、不同人的 dotfile，桌面可以長得完全不一樣
  • 因為改的是文字檔，所以可以直接 git 版控、跨機同步 ── 也剛好是 AI agent 最擅長處理的形式

stdin 的雷 ── 怎麼給 agent root 權限

  • Agent 透過 pipe 跟 shell 講話，沒有真正的 TTY → sudo 跳出密碼提示，agent 看不到、也輸入不了
  • 把密碼塞進 prompt 不安全；改檔案權限太粗暴；用 NOPASSWD sudoers 等於開後門
  • 我的解法：把 agent 跑在一個 tmux session 裡，這個 session 的 user shell 已經 sudo -v 過
  • sudo 的 timestamp cache（預設 15 分鐘）讓 agent 在同一 session 內呼出的 sudo 直接通過 —— 不需要再輸入密碼
  • 需要時我手動再 sudo -v 續杯，主控權永遠在我手上
# 我實際的開場流程
$ tmux new -s claude
$ sudo -v          # 在這個 session 緩存憑證
[sudo] password for e0pwr: ********
$ claude            # 在同一 pane 啟動 agent
# 之後 agent 跑的每一個 sudo dracut / sudo grub-mkconfig，
# 都吃這份 cache，不會卡 stdin。

CASE STUDY 01

把 RTX 3060 直通給 Windows VM

AMD RX 580 留給 host 跑 Linux，NVIDIA RTX 3060 整張交給虛擬機。
目標：在 Linux host 裡開 Windows VM，跑只能在 Windows 跑的東西，而且不犧牲遊戲效能。

  • 過程：4 個關卡，每一關都至少踩過一次雷
  • 產出：兩個自動化 shell script（gpu-enable-passthrough.sh / gpu-return-to-host.sh）

~ $ ls /sys/kernel/iommu_groups/

關卡 1 ── BIOS 沒開 VT-d

  • 第一個徵兆：/sys/kernel/iommu_groups/ 是空的
  • 明明 GRUB 已經有 intel_iommu=on，journalctl -k 也看到 DMAR: IOMMU enabled（誤導）
  • Agent 幫我 cross-reference：「這行 log 只代表軟體層啟用，不代表硬體真的在工作」
  • 正確判定：ls /sys/firmware/acpi/tables/ 必須有 DMAR 表
BIOS → Settings → Miscellaneous → Intel VT for Directed I/O (VT-d) → Enabled。 這一步全網很多教學跳過，因為「你應該已經開過了」。我沒開過。

/etc/default $ cat grub

關卡 2 ── kernel cmdline 四件套

GRUB_CMDLINE_LINUX_DEFAULT='... \
  intel_iommu=on \
  iommu=pt \
  pcie_acs_override=downstream,multifunction \
  vfio-pci.ids=10de:2504,10de:228e'
參數用途
intel_iommu=on啟用 Intel IOMMU
iommu=ptPassthrough 模式，host 損失極小
pcie_acs_override=...強制拆分 IOMMU group（需要 linux-zen）
vfio-pci.ids=...讓 vfio-pci 在最早期就綁住 RTX 3060

關卡 3 ── GPU 跟系統碟在同一個 group

# 預設 kernel 看到的：
Group 1:
  00:01.0  Intel PCIe Root Port (x16)
  00:01.2  Intel PCIe Root Port (x4)
  01:00.0  RTX 3060 VGA          ← 要直通
  01:00.1  RTX 3060 Audio        ← 要直通
  02:00.0  Samsung 970 EVO Plus  ← 系統碟！

# 同一 group 必須整組一起直通 → host 沒系統碟可開機
  • Z590 的 CPU PCIe root port 把它們塞在一起，這是主機板設計，不是 BIOS 能改的
  • 解法：linux-zen kernel 內建 ACS override patch，搭配 cmdline pcie_acs_override=... 把每個裝置拆成獨立 group
  • 裝完之後 RTX 3060 跟 NVMe 各自獨立，可以單獨直通
裝 linux-zen 又踩雷：nvidia-open 不是 DKMS 版，只為 stock kernel 編譯 → linux-zen 重建 initramfs 報 Failed to find module 'nvidia'。換成 nvidia-open-dkms 才解。

關卡 4 ── nvidia 一直搶在 vfio-pci 前面

  • 每次重開機：Kernel driver in use: nvidia —— 不是我要的 vfio-pci
  • 試過 softdep nvidia pre: vfio-pci → 在 dracut 環境沒效
  • 試過把 vfio-pci.conf 改名讓字母順序排前面 → 還是被搶
  • Agent 翻 /etc/dracut.conf.d/ 發現：EndeavourOS 自帶的 eos_nvidia_open.conf 把 nvidia 強制塞進 initramfs，比任何 softdep 都早
# 真正的解法：host 反正用 AMD 卡，根本不需要 nvidia driver
# /etc/modprobe.d/blacklist-nvidia.conf
blacklist nvidia nvidia_modeset nvidia_uvm nvidia_drm

# /etc/dracut.conf.d/zz-no-nvidia.conf
omit_drivers+=" nvidia nvidia_modeset nvidia_uvm nvidia_drm "

Agent 的價值在這一格體現：它讀過夠多 dracut 文件 + 夠多 EndeavourOS 包行為，才會去找這個別人沒寫的 eos_nvidia_open.conf。

VM + Looking Glass 端再踩一輪

network 'default' is not active
原因：firewalld 缺 libvirt zone。 解法：重裝 libvirt → 重啟 firewalld → 重啟 libvirtd → 啟動 network，順序不能錯。
Windows 只看到 1 顆 CPU
原因：QEMU 預設 4 vCPU 當 4 個 socket，Windows Home 只認 1 socket。 解法：明確指定 <topology sockets='1' cores='4' threads='1'/>。
Looking Glass: Failed to locate a valid output device
原因：RTX 3060 沒接螢幕，DXGI 找不到 output。 解法：HDMI dummy plug（假負載），約 NTD 100–200。
Windows 看到兩個螢幕（QXL + RTX 3060）
錯誤做法：整個移除 SPICE → LG client 連不到、音效沒了。 正確做法：保留 SPICE 拿音效/clipboard，把 <video><model type='none'/> 關掉 QXL。

CASE STUDY 02

osu! tablet 在 VM 裡 持續輸入時 會卡頓

  • 現象：一般使用流暢、auto mode 流暢，tablet 持續輸入時板子會跳
  • btop 顯示 vCPU 那 6 個核心都還有閒置（30–78%、loadavg ~4）—— 不是算力不夠
  • Agent 推論：USB device passthrough 路徑是 host USB → QEMU usb-host → emulated qemu-xhci → guest
  • 每個 USB packet 都 vmexit 進 host 處理一次再回去 → 連續輸入時延遲抖動很有感、停下來時鏈路空就不卡
診斷出「不是 CPU bound 是 USB jitter」這個結論，比解決它更重要 —— 它告訴我加 vCPU 或開 HT 都不會解，方向別走錯。
SLIDE 16 / 20
~ $ taskset --check

解法：把 emulator thread 隔離出去

# 1) host kernel cmdline
isolcpus=0-7
nohz_full=0-7
rcu_nocbs=0-7

# 2) libvirt domain XML
<cputune>
  <vcpupin vcpu='0' cpuset='0'/>
  ... (0-5 → CPU 0-5)
  <emulatorpin cpuset='6-7'/>
</cputune>
嘗試結果
isolcpus + emulatorpin✓ 卡頓明顯改善
iothread + virtio-blk✗ 現有 SATA bus 不支援
FIFO realtime scheduler✗ 卡 UEFI 開不了機

社群公認的「天花板」是整張 PCIe USB 卡直通，繞過 QEMU emulation。我目前到這裡已經夠順，先不買卡。

順手做的：Linux 端的 osu! 延遲調整

  • 不是每件事都要進 VM。Linux 直接跑 osu! 也能很順，只是要關掉 compositor 的 vsync
  • Hyprland 0.54（end-4 fork）的關鍵兩行：allow_tearing = true + windowrule = match:class .*osu.*, immediate 1
  • 滑鼠加速也要關：accel_profile = flat
# ~/.config/hypr/custom/general.conf
general { allow_tearing = true }

input {
    accel_profile = flat
    sensitivity   = 0     # Hyprland 中性值，不是歸零
}

# ~/.config/hypr/custom/rules.conf
windowrule = match:class .*osu.*, immediate 1
這裡 agent 直接幫我挑掉一個雷：osu-winello wiki 寫的 device { name = ... output = DP-X } 段落跟延遲無關（那是 Artist Mode 螢幕映射的修法），加上去等於佔記憶體。

心得 / Q&A

  • AI agent 不是「取代查資料」，是壓縮「讀文件 → 試 → 失敗 → 換解法」的迭代成本。我這次的 GPU passthrough，原本要花一週讀 wiki，實際兩個晚上做完
  • 它對 Linux / bash 場景特別猛 —— 因為訓練資料本來就是這個語言寫的
  • 真正的瓶頸是怎麼安全地給它權限（stdin / sudo / tmux），不是它聰不聰明
  • tool_use 是關鍵：能執行、能讀、能改 → 它才從「會講話的維基百科」變成「會動手的助理」
  • 它仍然會錯。我的角色是看著它跑、按 enter、隨時喊停，不是放生
如果你也是 Linux 使用者 —— 把你最痛的那件 sysadmin 雜事丟給它，會比你想像的順。
